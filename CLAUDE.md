# CLAUDE.md

OTProf UI: a static web app (`web/`) showing OTProf optical turbulence forecasts (from GFS) and a climatology (from
ERA5), and the Python pipelines (`pipeline/`) that compute its data. The model itself is the `pipeline/otprof`
submodule (its own repository: don't change it from here). Layout and setup: `README.md`, `pipeline/README.md`.

## Status

Unreleased and in development: rename or change formats, file names, keys and packages outright, with writer and
reader changed together, and rerun the pipelines instead of adding backward compatibility.

## Commands

```sh
cd web && npm run dev                      # dev server, data from pipeline/data/webui at /data/
cd web && npx tsc --noEmit                 # type check (npm run build: tsc + vite build)
cd pipeline && uvx ruff check --line-length 120 src forecast climatology
cd pipeline && uvx ruff format --line-length 120 <files>   # format only the files you changed
reuse lint                                 # every file must state copyright and license
uvx bump-my-version bump patch|minor|major # one version for web/ and pipeline/ (.bumpversion.toml), clean tree
```

Check UI changes in a real browser, at desktop and phone width (≤ 600 px has its own layout); the map needs WebGL.

## How it fits together

- **Data contract:** `docs/DATA_FORMAT.md` (`otprof-ui-forecast/1`, `otprof-ui-clim/1`). Writers in
  `pipeline/src/otprof_ui/` (`webui.py`, `webui_climatology.py`), reader in `web/src/data.ts`. Change all three
  together.
- **Texts** are markdown in `web/content/`, rendered into `index.html` at build time (`vite.config.ts`, plugin
  `content`; see `web/content/README.md`). No comments in these files: they end up in the page (`title.md` in the
  `<title>`). Links to `/forecast`, `/climatology`, `/licenses` and footnotes (`[^1]`) stay in the page; all others
  open in a new tab. All markdown is rendered at build time: the app ships no markdown renderer, so notes in the data
  (`meta.json` `"notes"`) are plain text.
- **Icons** are SVG paths in `web/src/icons.ts`, inserted at build time with `<!--icon:NAME-->` in `index.html`.
- **Licenses page** (`/licenses`): `web/content/licenses.md`, then the bundled npm packages with their license texts,
  generated by the build (`build.license` → `third-party-licenses.json`). The dev server shows the list of the last
  build in `web/dist/`.
- **Pipelines:** each step is resumable and `run.sh` holds a lock. `write_index` builds `index.json` from the cycle
  directories that exist. A watcher runs the forecast pipeline from the working copy, so uncommitted pipeline changes
  take effect at its next run.

## Licensing (REUSE)

- Every new file gets an SPDX header (`reuse annotate --copyright="Maximilian Pierzyna" --year=<year>
  --license=GPL-3.0-or-later <file>`); files that cannot hold a comment go into `REUSE.toml`.
- Third-party code or assets never go under our header. Keep them in their own file with the original copyright and
  license (as `web/src/icons.ts`, `web/src/github-mark.svg`), add the license text to `LICENSES/`, and list them in
  `README.md` (Third-party code) and in `web/content/licenses.md` (Third-party assets). npm packages bundled into the
  app are covered by the generated list.
- The credits of the input data (NOAA GFS; ERA5: CC BY 4.0, "Contains modified Copernicus Climate Change Service
  data") exist in `pipeline/src/otprof_ui/netcdf.py` (NetCDF attributes, CSV via the climatology's `meta.json`) and in
  `web/content/licenses.md`: keep them consistent.

## Conventions

- Comments are short and say what something is for or why it is so, in the existing style; British spelling in prose
  (colour). Python: ruff, line length 120. TypeScript: strict, no unused locals.
- Commit subjects: `Web app: ...`, `Pipeline: ...`, or a plain summary, listing the changes comma-separated; details
  as bullets in the body. Commit or push only when asked, on a branch, never on `main` directly.
- The repository is public: no details of anyone's own setup (host names, IP addresses, private paths, servers).
- Never read or print `pipeline/.env` or `pipeline/.rclone.conf` (credentials).
